# 인포가드 (InfoGuard)

2026 원티드 AI Championship 제안 프로젝트 — 정보유출 스캐너 + 사기 대응 훈련 모드.
전체 기획/의사결정은 `docs/` 참고 (제안서 최종본, 방향 확정 문서).

## 왜 이 구조인가

이 레포는 4인 역할 분담(A 모델학습 / B 스캐너엔진 / C 훈련모드 / D 화면·배포)을
그대로 폴더 구조에 매핑했다. 각 폴더 밑에 README를 넣어뒀는데, 실제 코드는 하나도
없고 "여기에 뭘 넣어야 하는지 + 왜 그런지"만 적어뒀다. 코드는 각자 짜면 된다.

```
infoguard/
├── frontend/        
├── backend/
│   ├── scanner/     
│   ├── training/    
│   └── shared/      
├── ml/              
├── prompts/        
├── sample_data/     
├── docs/            
└── infra/          
```

## 제일 먼저 할 일 (day0 체크리스트 기준)

1. `backend/shared/`의 탐지 엔진 입출력 형식을 팀 전원이 합의하고 확정 — 이게 안 정해지면
   엔진을 다 만들 때까지 훈련 모드 실시간 스캔 연동을 못 붙인다.
2. LLM 콘텐츠 필터 테스트 — Attacker AI 역할극 프롬프트가 실제로 거부당하는지 확인.
   여기서 막히면 `backend/training/attacker_ai/`, `prompts/attacker/` 설계를 다시 짜야 한다.
3. `ml/data_generation/`부터 손대기 — 다른 모든 것(스캐너 탐지, 훈련 데모 파일)이
   여기서 나오는 가짜 데이터에 의존한다.
