# backend/scanner/tests — 숨은 텍스트 테스트 문서

`hidden.py`를 만들고 임계값을 맞추는 데 쓰는 문서 묶음. 심사위원용 데모 샘플(`sample_data/`)과는
다른 물건이다. 이쪽은 **개발·회귀용**이고 보기 좋을 필요가 없다.

```bash
uv run python backend/scanner/tests/make_samples.py       # 문서 21개를 만든다
uv run python backend/scanner/tests/check_thresholds.py   # 놓침/오탐을 센다
```

임계값을 고칠 곳은 `backend/scanner/detectors/hidden.py` 맨 위다.
**한 번에 하나만 바꾸고 다시 돌린다.** 두 개를 같이 바꾸면 무엇이 효과가 있었는지 알 수 없다.

> 들어 있는 값은 **전부 가상이다.** 실제 개인정보도, 실제 API 키도 한 건도 없다.
> 숨긴 문장은 `models.is_injection()`의 키워드에 걸리도록 만들어 둔 가짜 지시문이다.

## hidden/ — 숨긴 문서 16개

한 파일에 수법 하나씩만 담았다. 여러 개를 섞으면 무엇 때문에 잡혔는지 알 수 없다.

| 파일 | 숨긴 방법 | `hidden.py`가 잡는 근거 |
|---|---|---|
| `01_docx_white_text.docx` | 흰 배경에 흰 글씨 | `color_unknown_bg` |
| `02_docx_tiny_font.docx` | 1pt 글자 (색은 검정 그대로) | `font_size` |
| `03_docx_vanish.docx` | 워드 숨김 서식 `w:vanish` | `vanish` |
| `04_docx_textbox.docx` | 텍스트상자 안의 흰 글씨 | `color_unknown_bg` |
| `05_pdf_render_mode3.pdf` | 렌더 모드 3 | `render_mode` |
| `06_pdf_transparent.pdf` | 투명도 0 | `opacity` |
| `07_pdf_tiny_font.pdf` | 0.8pt 글자 | `font_size` |
| `08_pdf_same_color_as_bg.pdf` | **파란 칸에 파란 글씨** | `color` |
| `09_xlsx_hidden_row_col.xlsx` | 숨긴 행 + 숨긴 열 | `row_hidden` · `col_hidden` |
| `10_xlsx_very_hidden_sheet.xlsx` | `veryHidden` 시트 | `sheet_very_hidden` |

| `14_txt_bidi_override.txt` | Bidi 재정의 (짧은 줄) | `invisible_a` |
| `15_txt_tag_chars.txt` | 태그 문자 | `invisible_a` |
| `16_txt_bidi_long_paragraph.txt` | Bidi 재정의 (**긴 문단**) | `invisible_a` |

**`04`는 두 가지를 한꺼번에 시험한다.** python-docx의 `paragraphs`로 읽으면 텍스트상자 안
글자는 아예 안 나온다 — 파서 커버리지 테스트다. 그런데 "텍스트상자에 있다"는 사실 자체는
신고 근거가 아니라서(정상 문서의 안내 상자도 텍스트상자다) 흰 글씨로 실제로 숨겨 뒀다.

**`08`이 특히 중요하다. 배경이 흰색이 아니다.** "흰 배경 + 흰 글씨"만 보는 검사는 이 파일을
그냥 통과시킨다. `parse.py`가 `bg_color`를 상수로 두지 않고 실제 채움색을 뽑는 이유다.

**`16`은 `14`와 같은 공격인데 문단만 길다.** 임계값을 되돌리면 무엇을 놓치는지 보여주는
파일이라 지우지 말 것.

## clean/ — 대조군 5개. **여기서 탐지 0건이어야 통과다**

전부 아무것도 숨기지 않은 정상 문서인데 **보이지 않는 문자가 들어 있다.**
발견 즉시 신고하는 구현은 5개 전부 빨간불이 된다.

| 파일 | 들어 있는 것 | 무엇이 이 파일을 살리나 |
|---|---|---|
| `01_txt_with_bom.txt` | BOM 1개 | 맨 앞 BOM 1개는 세지 않는다 |
| `02_docx_soft_hyphen.docx` | soft hyphen 8개 | 복원 검사 (걷어내도 새로 드러나는 게 없다) |
| `03_txt_emoji.txt` | ZWJ 3개 (짧은 문장) | 이모지 ZWJ 예외 |
| `04_txt_web_paste.txt` | ZWSP 2개 | 개수 3개 미만 + 50자 미만이라 밀도 판정 제외 |
| `05_txt_rtl_mixed.txt` | LRM/RLM/ZWNJ 4개 | 복원 검사 |

`03`은 훈련 모드(C)의 실시간 답장 스캔에서 특히 위험하다. 짧은 채팅에 이모지 하나면
개수와 밀도를 동시에 통과한다 — 채팅 한 줄마다 경고가 뜬다.

**아직 대조군에 없는 것: 변경내용 추적이 들어간 정상 문서.**
그래서 `hidden.py`는 지금 추적 삭제분(`deleted`)을 신고하지 않는다. 검토 중인 계약서에는
삭제 표시가 수백 개씩 들어 있어서 전부 신고하면 화면이 도배된다. **이 정책을 바꾸려면
그 대조군 파일부터 만들고 오탐이 몇 건 나는지 재고 나서 바꿀 것.**

## 맞춘 기록

### 1회차 (2026-09-10) — 파일의 숫자만 재봤다

`hidden.py`가 없어서 판정을 돌린 게 아니라, 파일에 들어 있는 문자 수와 밀도만 쟀다.
span 하나(문단·줄·셀 하나) 기준이다.

| 파일 | A급 | B급 | span 길이 | 밀도 |
|---|---|---|---|---|
| `hidden/13` 제로폭 | 0 | 36 | 70자 | 51.4% |
| `hidden/14` Bidi | 2 | 0 | 53자 | 3.8% |
| `hidden/15` 태그문자 | 57 | 0 | 120자 | 47.5% |
| `clean/01` BOM | 0 | 1 | 20자 | 5.0% |
| `clean/02` 자동 하이픈 | 0 | 8 | 166자 | 4.8% |
| `clean/03` 이모지 | 0 | 3 | 15자 | 20.0% |
| `clean/04` 웹 복붙 | 0 | 2 | 41자 | 4.9% |
| `clean/05` 아랍어 | 0 | 4 | 29자 | 13.8% |

여기서 두 가지가 보였다.

- **대조군의 A급은 전부 0이다.** A급은 정상 문서에 나올 이유가 없는 문자라서,
  임계값을 내려도 오탐이 늘지 않는다.
- **B급 밀도만 보면 대조군 5개가 전부 2%를 넘는다** (4.8% ~ 20.0%).
  게다가 정상 문서 쪽 숫자(20.0%)가 공격 쪽 숫자(3.8%)보다 커서 **어떤 선을 그어도 못 가른다.**
  숫자가 아니라 조건을 달아야 하는 경우다.

### 2회차 (2026-09-10) — 규칙을 코드로 만들고 돌렸다

**바꾼 것 1 — A급 임계값 3개 → 1개.**
글자 순서를 뒤집는 공격은 여는 문자·닫는 문자 2개면 성립한다. 3개로 두면 `14`와 `16`을
둘 다 놓친다(직접 되돌려 확인했다). 대조군 A급이 0이라 1개로 내려도 오탐은 그대로 0이다.

> 구현에서 A급에는 밀도 규칙을 쓰지 않는다. 1개부터 신고하므로 필요가 없다.

**바꾼 것 2 — B급에 조건 세 개를 달았다.** 숫자는 그대로 두었다.

| 조건 | 살아나는 대조군 |
|---|---|
| 50자 미만이면 밀도를 보지 않는다 | `01` `03` `04` `05` |
| 이모지 앞뒤의 ZWJ는 세지 않는다 | `03` |
| 걷어낸 뒤 **위험한 것이 새로 드러나야** 신고한다 | `02` `05` |

**중간에 한 번 틀렸다.** 처음에는 복원 검사를 "걷어냈더니 읽을 수 있는 문장이 나오는가"로
만들었는데, 그러면 어떤 정상 문서를 넣어도 통과한다(문자 몇 개를 뺀 원문이니 당연히 문장이다).
`clean/02`가 오탐으로 걸렸다. 그래서 **복원 방법을 구분**하도록 고쳤다 —
태그 문자 디코드·Bidi 되돌리기는 숨은 문장을 통째로 꺼낸 것이라 "읽을 수 있다"가 근거가 되지만,
단순 제거는 `models.is_injection()`이나 `rules.find_all()`이 **새로** 걸릴 때만 인정한다.

**결과: 놓침 0/16건 · 오탐 0/5건.**

## 다음에 임계값을 다시 맞출 때

1. `hidden.py` 맨 위 상수를 **하나만** 고친다.
2. `uv run python backend/scanner/tests/check_thresholds.py`
3. `[놓침]`이 있으면 그 임계값을 내리고, `[오탐]`이 있으면 올린다.
4. 둘 다 나오면 숫자로는 못 가른다는 뜻이다. 조건을 하나 더 단다.
5. 놓침 0 / 오탐 0이 되면 **바꾼 값과 날짜를 위 "맞춘 기록"에 추가한다.**

심사에서 "왜 2%냐"를 물으면 이 기록이 답이다.
