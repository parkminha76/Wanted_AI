# backend/shared — 탐지 엔진 입출력 계약 (★가장 먼저 확정)

**담당: B + C 공동 (첫날 확정 필수)**

## 왜 여기부터 시작해야 하는가

역할 분담 노트에 있던 내용 그대로: "탐지 엔진의 입출력 형식을 첫날 확정한다.
'문장을 넣으면 → 위험한 부분 목록이 나온다'는 함수 하나로 정의해두면, B가 만들고
C가 호출하기만 하면 된다. 이걸 안 정하면 C가 B를 기다리며 며칠을 버린다."

같은 탐지 엔진을 스캐너(문서 전체)와 훈련 모드(실시간 답장 한 줄)가 공유하기 때문에,
입력이 "문서 하나"든 "채팅 한 줄"든 같은 인터페이스로 다룰 수 있어야 한다.

## 여기 채워야 할 것

- 탐지 요청/응답 스키마 정의 (요청: 텍스트 or 이미지 + 문서타입, 응답: 필드별 탐지 결과 리스트 —
  필드명, 위치, 신뢰도, 위험도 등). 최종 필드 목록은 `docs/final-direction.md`의
  "탐지 대상 필드 목록" 표 참고 — 정규식/NER/CNN 세 갈래로 나눠서 처리하지만
  바깥으로 나가는 응답 형식은 하나로 통일해야 함.
- 이미지 파이프라인(CNN, 신분증)과 텍스트 파이프라인(정규식+NER)의 출력을
  같은 "위험 점수" 체계로 어떻게 합칠지 — 아직 미정, 여기서 정해야 함.
- 이 계약이 정해지기 전까지는 B/C 둘 다 이 인터페이스에 대해 목업(가짜 응답)으로
  각자 진행 가능하게 만들어두는 것도 방법.
